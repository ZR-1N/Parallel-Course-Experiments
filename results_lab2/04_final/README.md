# 04_final

## 版本说明

- 在 GKH 阶段保留 apply_left_rows 的行指针访问与 4 路循环展开优化。
- 在 bidiagonalization.cpp 中优化 Householder 变换的两个 TODO。
- 使用 ARM NEON 辅助函数优化连续点积与连续 scaled-add。
- 将左 Householder 中 w = v^T * B_sub 的计算从按列访问改为按行连续访问，提升 cache locality。
- 优化 B、U、V 更新中的连续行访问。
- 编译选项：-O2
- 随机种子：20260409

## 运行命令

bash test.sh 1 1 1 -O O2 -s 20260409

## 实验结果

- 通过样例数：5 / 5
- 总上二对角化耗时：3651.82 ms
- 总 GKH 迭代耗时：30509.9 ms

## 与 baseline 对比

当前 baseline 结果为：

- 总上二对角化耗时：10342.5 ms
- 总 GKH 迭代耗时：41470.2 ms

本版本相对 baseline：

- 上二对角化阶段耗时由 10342.5 ms 降至 3651.82 ms，加速比约为 2.83x。
- GKH 阶段耗时由 41470.2 ms 降至 30509.9 ms，加速比约为 1.36x。
- 总耗时由 51812.7 ms 降至 34161.72 ms，整体加速比约为 1.52x。

## 分析摘要

本版本是最终采用的综合优化版本。

Householder 上二对角化阶段取得明显加速，主要来自连续内存访问、减少列式访问带来的 cache 不友好，以及 NEON 对连续点积和向量更新的加速。

GKH 阶段保留了 apply_left_rows 的行指针访问与 4 路循环展开优化。该方案相比直接对 Givens 行/列旋转使用显式 NEON 更稳定。原因在于 apply_left_rows 的行访问连续性较好，而 apply_right_cols 在行主序矩阵中局部性较差，显式 NEON 或手动展开未稳定取得收益。

最终版本在保持 5 / 5 正确性通过的前提下，同时降低了上二对角化与 GKH 两个阶段的耗时。考虑到服务器为共享环境，单次运行耗时存在明显波动，报告中应结合消融实验结果与多次运行趋势进行分析，而不是仅依赖单次绝对耗时。
